# Maintaining WHIZZ444-YT-OS

This is the existing project repository: [WHIZZ444YT/WHIZZ444-YT-OS](https://github.com/WHIZZ444YT/WHIZZ444-YT-OS). The active product is a futures-only research and education platform. Use the current repository source and the [project charter](docs/futures-only-roadmap/00-PROJECT-CHARTER-AND-EXECUTION-RULES.md) as the source of truth; older upload instructions and build reports are historical.

## Change workflow

1. Clone the existing repository; do not upload a ZIP over the project or create a nested copy of its folders.
2. Start from the current `main` branch and create one feature branch for the selected roadmap Part.
3. Read the charter and selected Part completely. Audit current source paths and dependencies before editing.
4. Edit canonical source, data, tests and documentation. `dist/` is generated by `scripts/build_site.py`; do not edit it by hand.
5. Run the build, unit tests, structural/security validator and internal-link audit. Inspect generated routes and report the actual results.
6. Review the changed-file list and diff, then open one pull request to `main`. Do not commit directly to the production branch.

## Local build and quality checks

```bash
python scripts/build_site.py
python -m unittest discover -s tests -v
python scripts/validate.py
python scripts/audit_internal_links.py
```

To preview the generated site, serve `dist/` with a local static server. A local build without `SITE_URL` is intentionally `noindex`; configure the final HTTPS production origin only in the deployment environment before an indexable release.

## Deployment and data safety

- Vercel publishes the static build from `dist/`; verify its current Git connection, build settings and deployment before release.
- Cloudflare Worker credentials belong in Worker secrets. Supabase browser code may contain only the publishable key and must rely on RLS for user-owned rows.
- Never put API keys, service-role credentials, ingestion tokens, private Builder tokens or broker secrets in Git, browser code or URL query strings.
- Public API access does not itself grant real-time, redistribution, commercial display or AI/ML rights. Check current source terms and exchange entitlements before enabling a dataset.
- Keep listed currency futures and CME Bitcoin futures in scope. Keep unrelated equities, spot crypto, spot FX/CFD and prediction-market products out of the active product.
- Preserve existing user data, legacy baselines and useful futures/ICT routes. Prefer reversible route deprecation and archival over deletion.
