# 08 · Keep, merge, move and retire

These are proposed actions for future implementation PRs. Each deletion needs a caller inventory and a tested replacement where there was a public entry.

| Candidate | Decision | Safeguard |
|---|---|---|
| Home quote warning and equivalent status row | Merge into one status in the market snapshot | Preserve source and license disclosure. |
| Home market discovery and Desk market investigation | Keep both with distinct jobs | Shared registry, existing URLs and related deeplinks stay valid. |
| Repeated provider diagnostics across research surfaces | Move detailed diagnostics to Data Health, keep scoped status where used | Keep last verified time and degraded-provider evidence visible locally. |
| Academy / Lab / Entry Models overlap | Merge duplicated explanatory copy and show distinct rule scopes | Preserve routes, IDs, source roles and progress compatibility. |
| Lesson source details and resource shelf | Keep task-specific source placements and shared evidence renderer | Preserve offsets, direct links, metadata status and source ownership. |
| Practice and Strategy/Risk equivalents | Keep guided examples and authoritative engines | Test both entry points against the same behavior where shared. |
| Superseded CSS overrides and dead UI assets | Remove incrementally after reference and visual audit | Check generator, compatibility pages, runtime lookups, tests and both themes. |
| /research/, /tools/, /prediction-markets/, /legacy/ | Keep lightweight compatibility destinations while supported | Preserve useful redirect and noindex behavior. |
| Standalone ICT renderer and scoped service worker | Retire only after deployed parity and stale-client proof | Keep 19 hash mappings, nested lesson URLs, user storage, rollback and tested worker scopes. |
| Tracked dist/ and historical assets | Keep pending confirmed mirror inventory | Publish fresh build output. Remove tracked files only in a separately reviewed change with a mirror migration. |

## Procedure

1. Inventory HTML anchors, sitemap, scripts, service-worker registration, storage keys, documentation links and provider consumers.
2. Choose the owner and map old route or ID to its successor. Write parity checks before removing an entry point.
3. Remove in small slices. Compare standard and cutover manifests, browser state, user record imports and link audit. Archive the route table and keep a reviewed rollback deployment.
